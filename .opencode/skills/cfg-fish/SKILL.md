## Activation Contract

Load this skill when the user asks to change fish shell configuration — aliases, PATH, functions, environment variables, tool integrations (fzf, zoxide, starship), plugins (fisher), abbreviations, or any `fish` keyword. Follow the READ→PLAN→APPLY→VALIDATE→VERSIONAR pipeline from `cfg-common.md`.

## Hard Rules

- ALWAYS read `AGENTS.md` before suggesting heavy init scripts. 3.7 GiB RAM — do NOT add heavyweight init processes (large completions, slow startup tools) without user confirmation.
- Fish syntax is NOT POSIX sh compatible. Always use fish-specific commands: `set` (not `export`), `fish_add_path` (not `PATH=`), `alias`/`abbr` (not `alias name=value`), `source` (not `.`).
- NEVER edit `fish_variables` — it is auto-generated by fish and already excluded in `.chezmoiignore`.
- NEVER edit `fish_history` or `fishd.*` — these are runtime state, not config.
- Run `fish -n {file}` after ALL edits. If any file fails syntax check, BLOCK the commit.
- Preserve existing structure: `config.fish` is the entry point, `conf.d/` for drop-in configs, `functions/` for custom functions, `completions/` for custom completions.
- Delegate all chezmoi operations to `cfg-chezmoi`. Never run `chezmoi` commands directly.
- Commit message format: `type(fish): {description}`.

| Situation | Action |

| User requests function creation | READ → PLAN (function name, body, description) → APPLY (create `functions/{name}.fish`) → VALIDATE → VERSIONAR |
| User requests fzf integration | READ → PLAN (keybindings, preview settings) → APPLY (add `fzf --fish \| source`) → VALIDATE → VERSIONAR |
| User requests zoxide integration | READ → PLAN (init command) → APPLY (add `zoxide init fish \| source`) → VALIDATE → VERSIONAR |

## Execution Steps

### READ

1. Locate fish config in chezmoi source:
   - `~/.local/share/chezmoi/dot_config/fish/config.fish` — main config entry point
   - `~/.local/share/chezmoi/dot_config/fish/conf.d/` — drop-in configs (if any)
   - `~/.local/share/chezmoi/dot_config/fish/functions/` — custom functions (if any)
   - `~/.local/share/chezmoi/dot_config/fish/completions/` — custom completions (if any)
   - `~/.local/share/chezmoi/dot_config/fish/fish_plugins` — fisher plugin list (if any)
2. Read full config contents
3. Read `AGENTS.md` for hardware constraints (RAM, GPU, display)
4. Return current state: all aliases, PATH entries, env vars, functions, tool integrations, hardware context

### PLAN — Alias / Abbreviation

Fish supports two types of shorthand commands:
- **Alias** (`alias`): creates a function wrapper. Syntax: `alias name "command args"`. Persistent in config.fish.
- **Abbreviation** (`abbr`): expands inline as you type. Syntax: `abbr -a name command`. Can be `--global` (`-g`) or `--universal` (`-U`).

```fish
# Alias (function wrapper, runs immediately):
alias g "git"
alias gc "git commit -m"

# Abbreviation (expands inline, press Space/Enter):
abbr -a gco git checkout
abbr -a gst git status
```

### PLAN — PATH Modification

Fish uses `fish_add_path` to manage PATH. Always use it instead of directly manipulating `$PATH`:

```fish
# Add a directory (appended by default):
fish_add_path /home/juan/.local/bin

# Prepend a directory:
fish_add_path -P /usr/local/bin

# Move an existing entry to the front:
fish_add_path -m /home/juan/.local/bin
```


### PLAN — Environment Variable

Fish uses `set -gx` (global + export) for persistent environment variables:

```fish
# Global and exported (available in subprocesses):
set -gx EDITOR nvim

# Global only (not exported):
set -g MY_VAR value

# Universal (persists across sessions, not in config):
set -U fish_color_command blue
```

```text
# Plan: set VISUAL to nvim
# Edit: append 'set -gx VISUAL nvim' to config.fish
```

### PLAN — Function Creation

Fish functions are stored as individual files in `functions/`. One function per file, filename = function name:

```fish
# functions/mkcd.fish
function mkcd
    mkdir -p $argv[1] && cd $argv[1]
end
```

For simple one-liners, users can also define functions inline in `config.fish` with `funcsave`:

```fish
function mkcd
    mkdir -p $argv[1] && cd $argv[1]
end
funcsave mkcd
```

### PLAN — Tool Integration (fzf, zoxide, starship)

Tool integrations use the tool's init command piped to `source`:

```fish
# fzf keybindings (Ctrl+R history, Ctrl+T files, Alt+C dirs):
fzf --fish | source

# zoxide smart cd (replaces cd):
zoxide init fish | source

# starship prompt:
starship init fish | source
```

### APPLY

Edit chezmoi source files:
- **config.fish**: Append new aliases, `fish_add_path` calls, `set -gx` vars, `source` lines for tool integrations
- **functions/{name}.fish**: Create new file with function definition
- **conf.d/{name}.fish**: Create new drop-in config file
- **completions/{name}.fish**: Create new completion file
- **fish_plugins**: Append plugin name on a new line
- Preserve all existing lines, comments, blank lines, and whitespace
- NEVER create or edit `fish_variables` or `fish_history`

### VALIDATE

```bash
# Validate ALL modified fish files with fish -n (syntax check):
fish -n ~/.local/share/chezmoi/dot_config/fish/config.fish

# If conf.d/ files exist:
fish -n ~/.local/share/chezmoi/dot_config/fish/conf.d/*.fish

# If functions/ files exist:
fish -n ~/.local/share/chezmoi/dot_config/fish/functions/*.fish

# If completions/ files exist:
fish -n ~/.local/share/chezmoi/dot_config/fish/completions/*.fish
```

- Exit code 0 for ALL files → pass, continue to VERSIONAR
- Any file exits non-zero → fail, BLOCK commit, show error output with failing file path
- If `fish` binary not found: "WARNING: fish binary not found — cannot validate config syntax. Showing diff for manual review:"

### VERSIONAR

Delegate to `cfg-chezmoi`:
- `chezmoi re-add` modified config file(s)
- First-add for new files (functions/*, conf.d/*, completions/*)
- `git commit -m "feat(fish): {description}"`
- Return commit hash and diff to user

## Output Contract

Return to `cfg` orchestrator:
